# Data Inventory and Dictionary

## Provenance

All analytical records listed below are generated by `src/generate_synthetic_dataset.py` using a fixed random seed. The retailer, customers, products, carriers, dates, and prices are fictional. The dataset is for pipeline and analysis practice only; it is not external empirical evidence. The original tutorial dataset is not redistributed.

## Tables and grains

| File | Grain | Primary key | Row count in current generation | Relationship |
|---|---|---|---:|---|
| `orders.csv` | One row per customer order | `order_id` | 1,440 | `customer_id` → customers; `carrier_id` → carriers |
| `order_lines.csv` | One row per order-product line | `line_id`; also unique `order_id + line_number` | 3,601 | `order_id` → orders; `sku_id` → products |
| `customers.csv` | One row per fictional customer | `customer_id` | 80 | Parent dimension for orders |
| `products.csv` | One row per fictional product/SKU | `sku_id` | 24 | Parent dimension for order lines |
| `carriers.csv` | One row per fictional carrier | `carrier_id` | 6 | Parent dimension for orders |

Counts are expected for generator seed `20261023`; regenerate through the script if files are changed.

## Field dictionary

### `orders.csv`

| Field | Type | Meaning / rule |
|---|---|---|
| `order_id` | Text | Synthetic unique order identifier. |
| `customer_id` | Text | Fictional customer key. |
| `carrier_id` | Text | Fictional carrier key assigned to the order. |
| `market` | Category | `US` or `IN`; must match customer and carrier market. |

## Data quality expectations

The primary synthetic files are intentionally generated as a clean, relational exercise. Verify key uniqueness, valid types, foreign-key joins, currency-market consistency, date order, and order/line reconciliation. `data/fixtures/orders_validation_fixture.csv` and `data/fixtures/order_lines_validation_fixture.csv` intentionally contain invalid rows (duplicates, malformed values, and orphan keys). They are optional inputs for a separate ingestion-rejection test; the completed project did not implement n8n automation. Do not merge these fixtures into the clean analytical tables or KPI analysis.

## Important exclusions

There is no inventory-on-hand table, stock movement, purchase order, supplier, actual replenishment lead time, or real carrier event history. Do not calculate stockout, safety stock, reorder point, supplier performance, or real-world carrier performance from this dataset.
